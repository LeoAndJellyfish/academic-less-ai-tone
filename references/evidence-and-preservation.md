# 主张核对与信息保全

V24沿用V23的事实保全细则，供包含数据、引文、方法及研究结论的任务逐项核对。

## 先识别文本任务

- 区分论文的引言、方法、结果、讨论，以及讲座、论坛发言和研究报告。遵守目标期刊、会议或作者已有的格式与语体。作者提供既有写作样本时，参考其稳定习惯。
- 依读者的专业背景和阅读目的选词，优先采用作者、用户及本学科熟悉的惯用说法，同一概念沿用稳定称呼。少见或临时拼接的复合名词先核所指，再选已有表达。必要的专业术语依其用途保留，按读者需要解释；“常见”以目标读者和学科为参照。
- 讲座、汇报和摘要中的各句服务于当前问题：解释方法作用、呈现发现、交代关键条件或支持决定。运行维护与复现细节依体裁及任务要求安排在正文、备答或附录。先列用户指定的必留项，保留在指定位置；完整改写保存全部有效信息，摘要或选编依约定范围选择内容。重要范围、依据和判断强度随相应主张交代。
- 新写作先核实资料，再组织论点。改写现有稿件时，先列出各段的**主张、所据材料、推论和适用范围**。缺少支撑的学术结论标记为待补证；不得编造来源、数据或机制。
- 篇幅按用户约定执行。有明确字数区间时，先写全事实和关系，再计数修订；恢复省略的数据角色、比较基准和限定，可改善过短正文。没有字数约定时按论证所需篇幅写。原资料确实不足以支持约定篇幅时，在附注说明具体缺项。
- 引文、术语、变量定义、样本、数值、单位、统计结果、限定词、图表及章节指代原样核对。保留有依据的因果方向与判断强度。
- 压缩含“绝大多数情况下”“通常”“部分”“仅在”等量词的句子时，核对量词约束的对象与范围。可换用等义表达，不能省去限定后扩大命题。
- 写作采用输入或已核验来源支持的事实；编辑时新增资料须注明来源。学科常识可以帮助识别疑点，不能代替资料补充设计细节。例如，“观察性研究”未明说分组方法时，不追加“未随机分组”。置信区间跨零时，保留区间与原有判断，不另写“没有效果”或含义不同的显著性结论。
- 作者提供的事实卡、表格或原文摘录已构成当前编辑所据材料。针对其中明确给出的事实，直接保留并核对转写，无需重复要求作者提供相同数据；材料之外的独立断言才列为待核。

事实卡可能同时含正文命题、来源定位和编辑提醒。正文呈现对象、方法、观察及有据解释；页码、改稿禁令与核查提醒用于内部审校。资料已将一个判断标为“作者推测”时，正文以相应归属和语气表达；例行核查内部留存；附注保留影响使用或需要作者裁决的资料缺口。

## 主张与证据预审

编辑前在内部逐句建立对应关系，不必向读者展示工作表。将每个独立主张拆成可核查的部分：**谁提供资料、谁发布文本、研究对象与范围、观察值及单位、预测与实测的时间状态、引文来源、统计判断、因果或推广判断**。对照输入资料逐项标记“有直接依据”“仅有较弱依据”“没有依据”“与依据冲突”。保留直接有据的部分；较弱依据须收窄到资料实际覆盖的对象与时间；无据或冲突的断言须在正文中删除或纠正。待核说明不能代替正文修改。

内部另列一张**关系清单**：对象、指标或动作、关系方向、比较对象、样本／时段、数值角色、判断强度。比较命题保留两端与方向，必要时将高低关系与组别、数值合写；两组数字原样出现仍可能漏掉原稿另提出的比较结论。完整比较已呈现该方向时，后文的同义总结与前句合并。原稿的独立比较结论、范围与限定逐项保留。参数大小、观察结果和作者解释分别核对。涉及数值时，逐项检查“哪个对象的哪个指标，在什么条件下是多少”；改换排列顺序后再次检查归属。平均值另核对统计单位，例如每所学校的学生数、每名学生的得分；句子主语须与该单位一致。 检测或评价的对象与属性分别核对，例如“检测向量的正交性”中的向量和正交性都须有明确落点。统计句分别写清因素、被分析的指标及它们的关系；“指标X的因素A与因素B交互显著”可写为“因素A与因素B对指标X的交互作用显著”，具体措辞依据设计和检验结果。研究设计中的每类数据须保留测量内容与角色，城市层面的某指标和企业记录应分别交代。

多个对象对应多个数值时，正文须使每个数值具有唯一且明确的对象、指标和条件。可同句按同一顺序列出对象和数值，或逐项陈述；清楚的跨句配对也可保留。“依次／分别”前的对象清单须与后面的数值数量、顺序一致；上一句的不同排序或不完整清单无法承担此处归属。不同组别的“更强”“更显著”等判断分别落到各自组别；合句仍保持这种对应。 “数量、比例、水平”等测量名词须有明确的被测对象。地点、群体或类别通常是分组条件；句中写清所计事物，例如“不同类型保护区记录的入侵植物数量”。比较维度从纬度改为类型、从行业改为地区时，当前句重新核对所比较的指标，避免省略后改成地点或群体自身的数量。

特别检查三种易混淆关系：

1. **来源归属**：发布者、引用者、估计者及实测者分别核对。引用他人估计的报告，不能写成报告作者直接测量，也不能交换发布机构。
2. **证据状态**：预测保持预测，计划保持计划，观察值保持观察值；“数值较高”不自动成为“显著提高”，跨样本、跨任务及跨地区的结论需要相应资料。需在正文交代的资料缺口，以具体记录、测量或检查项说明，范围贴近相关结论。转述工作记录时，区分完成报告、工具检查和用户确认，各自按来源实际覆盖的范围表达。
3. **适用范围**：两份文献中的术语用法只写到这两份文献；一个测试集的表现只写到该测试集。原稿中的宏观判断删去后，不用较弱但仍超出材料的概括补位。

一份资料若列出总体项目和其中的子集，分别核对两组成员与各自的关系。例如，五个变量与结果相关，其中四个出现调节关系时，正文先写清五个，再逐一写出调节关系对应的四个名称。“前四种”“上述四者”可能因排列顺序造成成员错配；用明确名称交付。方法、结果和讨论中出现的“多数”“少数”“部分”也要与原资料逐句对齐。

分类名、章节标题和分析标签先核原词与解释。某个标签列入“困境”时，仍要查它指向的机制及评价方向；“行政效率”与“行政低效”表达不同命题。材料只给标签、没有解释时保留原词，必要时向作者核实。改写不得依据周围语气猜测其反义词。

复合名词和紧缩术语先在原文中确定动作与指代，再安排句子。例如，儿童福利服务中的“发现报告”指发现并报告需帮扶对象这一工作环节，不能改为“研究报告发现”或漏掉报告动作。涉及它与“协作机制”的关系时，分别写明环节作用与机制状态；“其协作机制”会使待优化对象移位。资料若未解释复合词，沿用原词并列为待核；不凭词形拆造机构、文件或研究结论。

数值多于一组时，先在内部核对“类别／时间／数据子集／指标／数值”的逐项对应。只有来源给出增长或下降，才用“增至”“降至”；基期与末期相同的类别写“保持”。一个指标可在验证集和测试集分别计算，两个指标也可能仅在测试集同时报告，不能据“两项指标、两个数据子集”概括为一一对应。

监测资料的病例类别先按原文口径呈现。来源写“基础疾病合并某感染死亡病例”时，正文可写“属于基础疾病合并感染死亡类别”；“感染所致”或“单纯由感染导致”加入因果归属或额外分类条件，须有来源支持。发布日、资料覆盖期和采样周分别核对。

若事实卡只给研究设计或局部结果，正文陈述这些资料即可。不要为凑篇幅增加“现有结论仅适用于……”等原资料中并无对应结论的句子；也不要反复以否定句列举已经删除的全国性、机制性或评价性主张。只有删去限定会改变现有命题的含义时，才在正文保留该限定。

统计量按其自身的无效值核对。比值比、风险比的无效值通常是 1；均值差、回归系数等差值尺度的无效值通常是 0。核查置信区间时先辨认指标与比较基准，避免在正文或待核说明中写错“跨零”“跨一”。没有检验结果时，可说明当前资料未给检验，不能自行补算或宣称显著性。

写成正文后再逐句反查：每个数字、年份、机构、引文和独立结论对应哪条资料；每条要求保留的事实是否仍在正文；每条未获支持的草稿断言是否已从正文消失。若某句只能依赖原稿自身、常识或编辑者推测，删去该句或列入待核。发现“附注说已删除，正文仍保留”时，以正文为准，重新修改正文。附注也须与实际改稿一致，不得声称保留了已删的句子，也不得加入未经核验的统计解释。


## 实际篇幅

明确要求汉字数时，计数仅覆盖正文，排除附注、字段名和审校记录。有本地 Python 时可执行 `scripts/measure_body.py --input 输入.json --min 下限 --max 上限`；输入含 `revision` 字符串，输出实测汉字数与达标状态。其他计数口径按用户要求使用相应工具。超出区间时，按任务约定的返修次数修订正文并重新测量；附注中自行声称达标无效。实验达到预定次数后保存正文及实测值，记录未达标结果。返修继续保护事实与关系，优先补回已有信息或压缩重复表达。首次稿及返修稿在实验中分别保存。

## 交付前核对

逐段检查事实、引文、数字、术语、推论方向和不确定性是否与已核资料一致。逐一对照原稿与改稿中的数字、单位、作者及年份，核查有据内容是否遗漏或改值；核对机构名称与数据来源的归属。原稿自身仅供寻找待审主张，缺少来源支持的原稿内容不得因行文顺畅而留在正文。检查所有改动能否说明对应的论证问题；恢复仅因字面形式而被删掉的有效论证。对保留句另核查主语、语序和相邻衔接，删减重复的提醒语，确保必要限定贴近其所约束的结果。完整文稿的待核问题放在正文后；若输入仅有一句空转文字，直接交付待核问题。

当事实卡或摘录被指定为唯一可核来源，且本地可执行 Python 时，定稿前运行随附的 `scripts/claim_preflight.py`。输入 JSON 含 `source`（事实卡全文）、`draft`（原稿）和 `revision`（**仅修订正文**）三个字符串；在本技能目录执行 `python scripts/claim_preflight.py --input 输入.json --strict`，其他工作目录使用脚本绝对路径。脚本列出来源中未见的范围词、未来安排、强判断、数字、技术缩写与方法动作，并提示来源量词可能遗漏、列表成员可能被含混指代、有据解释可能丢失。`opposite_term_candidates` 提示“行政效率／行政低效”等来源与正文的反向词；升降等方向词可能指向不同指标，只列为人工复核候选。`style_candidates` 列出高频否定转向、提示壳与重复指标口径候选；对每条候选先试写证据先行的直陈句，核对语义后取舍。`--strict` 遇到来源外的正面地域／全称主张、后续计划或“行政效率／行政低效”类分析标签候选时以状态码 2 停止定稿。逐项审查警报涉及的整句：证据不足的主张先从正文中删除或收窄，再重新运行；确有来源支持而被词面规则误报时，记录证据和人工裁决。附注的说明不能代替正文修改。其他警报同样需要读句判断，尤其是新增方法、遗漏数值与集合成员；没有本地执行条件时按同一清单人工核对。
